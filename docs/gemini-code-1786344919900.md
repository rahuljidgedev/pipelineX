> **System Version:** 3.0.0 (Antigravity Architecture)
> **Target Paradigm:** AI Research Factory & Deep-Tech Orchestration
> **Core Frameworks:** Google Antigravity SDK, Gemini API (Managed Agents), Python 3.11+, Jupyter Kernels

---

## 1. Executive Summary: The Strategic Crossroads

PipelineX has reached a critical architectural divergence. Based on market realities and global technical trajectories, we have evaluated two distinct paths:

1.  **Path A: The AI Software Factory (Enterprise Utility)**
    *   **Focus:** Competing with commercial AI coding agents to generate KMP/Android apps via automated PRD fulfillment.
    *   **Dynamic:** Highly saturated market, focused on cost-reduction and deterministic compilation loops.
2.  **Path B: The AI Research Factory (Deep-Tech Moonshot)**
    *   **Focus:** A non-deterministic scientific discovery engine focused on quantum technologies, nanotechnology, precision farming, and space tech.
    *   **Dynamic:** High barrier to entry, focused on societal impact, digital-twin simulations, and verifiable scientific knowledge. 

**Decision:** PipelineX will pivot toward **Path B**, transitioning from a software engineering tool into a synthetic exocortex for scientific research.

---

## 2. Infrastructure Pivot: Adopting Google Antigravity

To compete with global-scale systems, the manual LangGraph and Docker orchestration must be upgraded. PipelineX will now be built on the **Google Antigravity SDK and Gemini API**, utilizing its native agent-first paradigm.

### Why Antigravity?
*   **Managed Linux Sandboxes:** Instead of building custom Docker execution wrappers for the `QA Agent`, the Gemini Antigravity Agent API natively provisions secure Linux sandboxes with built-in `code_execution` and file management.
*   **Context Compaction:** Deep-tech research requires massive context windows (reading full scientific papers). Antigravity automatically compacts context to support long-running, multi-turn scientific sessions.
*   **Parallel Orchestration:** Antigravity 2.0 allows the orchestration of multiple agents executing tasks asynchronously, perfectly aligning with our required "Scientific Swarm" architecture.

---

## 3. The New Multi-Agent Scientific Swarm

The traditional SDLC agents (PM, Dev, QA, Reviewer) are translated into a lab-native topology:

| Legacy Node (Software) | New Antigravity Node (Science) | Role & Capabilities |
| :--- | :--- | :--- |
| **PM Agent** | **Principal Investigator (PI)** | Uses `google_search` and `url_context` to synthesize scientific literature and formulate testable hypotheses. |
| **Dev Agent** | **Theorist / Modeler** | Writes simulation code (e.g., Qiskit for quantum, GROMACS for molecular dynamics). Contains a **Physics Checker** constraint to prevent thermodynamic/logic hallucinations. |
| **QA Agent** | **Experiment / Execution** | Deploys generated models into the Antigravity Linux Sandbox via the `code_execution` tool to run high-throughput computational simulations. |
| **Auditor Agent** | **Data Analyst** | Parses output matrices, stress-test reports, and spectral data to determine if the PI's hypothesis holds true. |

### The Human-in-the-Loop Gate
Instead of approving app builds or PRDs, the human scientist acts as the **Epistemic & Safety Gate**:
*   Approving physical simulation parameters before they are deployed to expensive HPC clusters or physical robotic labs.
*   Reviewing anomaly reports generated by the Data Analyst agent to find novel discoveries.
